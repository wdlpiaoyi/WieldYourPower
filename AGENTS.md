# AGENTS.md

Forge 1.20.1 mod `wieldyourpower` (力量掌控). Java 17, official mappings, Forge `1.20.1-47.3.10`, Gradle 8.8 wrapper, daemon disabled. Ships client + server code.

## Commands
- Build: `.\gradlew.bat clean build --console=plain` from the repo root. `JAVA_HOME` must point at JDK 17.
- Dev runs: `.\gradlew.bat runClient` / `runServer` (working directory `run/`).
- No tests, linter, formatter or typecheck tasks exist (`src/test` has only empty dirs). "Verify" = build succeeds + manual in-game check; do not invent test commands.

## Version bump (easy to miss)
Bump BOTH or they drift: `gradle.properties` `mod_version` and `WieldYourPower.VERSION`. Output is `build/libs/wieldyourpower-1.20.1-forge-<ver>.jar`.

## Build quirks
- Cloth Config is a required compile dependency, read from `modpackModsDir` (`build.gradle`, default project-relative `libs/`, which is gitignored; override with `-PmodpackModsDir=...`). The build fails without a `cloth-config-*.jar` there; runtime also requires Cloth. Curios is an optional (soft) `compileOnly` dependency read from the same folder (`curios-*.jar`): required to compile the Curios integration, but absent at runtime the integration is skipped (guarded by `ModList.get().isLoaded("curios")`).
- Do not rewrite `gradle.properties`/`.java` with PowerShell `Set-Content -Encoding UTF8` (adds a BOM and breaks compilation); use the edit tools.

## Config
- Config lives in `WYPConfig` (COMMON) and is surfaced through the Cloth screen (`client/cloth/ClothScreens`, plus the custom `QuickAddEntry` row reused by every list). Double-valued settings are edited as text fields holding `String.valueOf(value.get())`, so every `setDefaultValue` for them must be spelled exactly like that text (`"1.0"`, never `"1"`) or Cloth marks an untouched entry as non-default; keep the default equal to the spec's `defineInRange` default too, since that string is what the entry's reset button writes. Tooltips go through the `tip(...)` helper in `ClothScreens`: Cloth renders a `Component[]` tooltip one element per line and never wraps, so a long single `Component` would overflow the window.
- Filter lists use the comma form `key,value` (a `:` inside an id is kept). Legacy `key:value` is migrated on load (`FilterSyntax.normalizeAll`; `killHonor` via `ConfigMigration`, the ally list on player-NBT load). Write the comma form in new code/UI.
- Other general toggles: `creativeBreaksProtectedBlocks` (creative may break blocks other mods protect), `blockBreakerEnabled` (admin Block Breaker item), `blockProtectionBypass` (keyword-driven third-party block-protection switch).

## Networking
- `WYPNetwork.VERSION` (currently `"4"`) is the channel protocol version; bump it whenever packet fields change so mismatched clients are rejected.

## Mixins
- MixinGradle 0.7.38 + Mixin 0.8.5 processor. Config: `src/main/resources/wieldyourpower.mixins.json`; refmap wired via the `mixin { add ...; config ... }` block in `build.gradle`; `MixinConfigs` is also set manually in `tasks.jar`.
- Add new mixins to that config: `mixins` = both sides, `client` = client only (package is `net.wieldyourpower.mixin`).
- `injectors.defaultRequire = 1`: a failed injection crashes at runtime, not at build time. All current mixins target vanilla; a mixin aimed at an optional third-party class would need its own config with `"required": false` + `"defaultRequire": 0`.
- Example: `LivingEntitySetHealthMixin` rewrites `setHealth` args with `@ModifyVariable` (refmap maps `setHealth -> m_21153_`).

## Access transformer
`src/main/resources/META-INF/accesstransformer.cfg` currently exposes (SRG names): `LivingEntity.die/dead/DATA_HEALTH_ID/lastHurt`, `Entity.unsetRemoved/isAddedToWorld`. Add an entry before touching other private/package vanilla members.

## Architecture
- `capability/` = per-player self-limits (`IPlayerLimits`, UUID fallback); `network/` syncs them; `command/` registers `/wyp`; `common/*Events` are Forge event subscribers; `client/` enforces movement/mining client-side; `compat/` holds the keyword-reflection helpers guarded by the ASM bytecode scans in `ClassSafety` (`BossDespawnCompat` default OFF; `BlockProtectionBypass`, which toggles a third-party block-protection switch, default ON); `util/` holds `FilterSyntax`/`EntityMatcher`/`KillUtil`/`FrozenEntities`/`ForcedRemoval`/`RemovalGuard`/`ForceBlockBreak`.
- Speed limits are client-enforced (`client/ClientEvents`), while kill/freeze/protection are server-authoritative.
- `common/AuthorsFavorPresence` keeps a strong reference to favored entities and re-adds them if they vanish from the level, guarding against reflective "deep removal" that bypasses `remove`/`setRemoved`. `BlockProtectionEvents` waits one tick after a creative left-click and force-breaks only if the block is still there and unchanged and the held item `canAttackBlock`s it (vanilla semantics, so swords do not break blocks), so vanilla and vein miners run first. `BlockPlacementEvents` releases cancelled placement events (both sides) for a creative player holding a block item (not yet verified in-game).
- The "no update" permission (`util/NoUpdateMode`) has three independent sources that never revoke each other: `PERMITTED` (API `setSurvivalNoUpdateAccess`), `CURIOS` (tagged-curio scan) and `GRANTED` (`/wyp access grant|revoke noupdate`, perm level 2). Only the command grant is persisted (capability flag `IPlayerLimits.isNoUpdateGranted`, NBT key `NoUpdateGranted`); `NoUpdateMode.clear` on logout drops all three and `NoUpdateEvents.onLogin` restores the persistent one and re-syncs the client. Suppression has three layers and all of them must stay (player-facing name: "update suppression" / 「抑制更新」): `mixin/LevelSetBlockMixin` rewrites `Level.setBlock`'s flags (drops `UPDATE_NEIGHBORS`, sets `UPDATE_KNOWN_SHAPE`); `mixin/LevelNotifyMixin` **and** `mixin/ServerLevelNotifyMixin` cancel the neighbour-notify entry points for as long as the mode suppresses - `updateNeighborsAt`, `updateNeighborsAtExceptFromFacing` and both `neighborChanged` overloads on both `Level` and `ServerLevel`, plus `updateNeighbourForOutputSignal` on `Level` only. Both mixins are required: `ServerLevel` overrides all four notify methods and forwards them to its `NeighborUpdater`, while the `Level` bodies are only a Forge event hook (`updateNeighborsAt`) or a literal `return` (both `neighborChanged`), so virtual dispatch on a server level never reaches a `Level` injection - that, not the setBlock flags, is why a redstone torch broken with the key still retracted a piston, and why the hand-written `onPlace`/`onRemove` notifications of `RedstoneTorchBlock`, `RedStoneWireBlock`, `DiodeBlock` and `LeverBlock` have to be silenced on `ServerLevel` itself. Cancelling at the `ServerLevel` entry points (rather than inside the `NeighborUpdater` implementation) also means the update is never queued and cannot be replayed after the action window closes; `ServerLevel.blockUpdated` only forwards to `updateNeighborsAt` and needs no injector of its own. `sendBlockUpdated` must never be suppressed - clients have to stay in sync. The acting player's window is opened by `mixin/ServerPlayerGameModeMixin` around `destroyBlock` and `useItemOn` (right-click interactions), plus `util/ForceBlockBreak`. The third layer, `mixin/GameEventDispatcherMixin`, drops `GameEventDispatcher.post` while the mode suppresses, which is what keeps sculk vibrations off: sculk sensors, shriekers, catalysts and wardens only learn about the world through `GameEvent`s (`BLOCK_DESTROY` from `Block.playerWillDestroy`/`Level.destroyBlock`, `BLOCK_PLACE` from `BlockItem.place`, `BLOCK_ACTIVATE`/`BLOCK_OPEN` from right-click use), and the dispatcher is fed solely by `ServerLevel.gameEvent`, so `post` is the single choke point. It is cancelled there rather than in `ServerLevel.gameEvent` on purpose: the Forge `VanillaGameEvent` hook in front of it still fires, so other mods keep observing the events.

## Hard constraints (project rules)
- Never edit other mods' files or save data (`SavedData`); prefer generic, non-mod-specific approaches. No per-mod compat code/mixins.
- Stay within normal Java/Forge reach: events, Mixin method-body injection, access transformer. Do NOT use launch plugins, ASM class transformers, reflection into modlauncher internals, or `Unsafe`. (Some mods do; those are out of scope for this mod even when they make it lose.)
- `BlockProtectionBypass` must stay keyword-driven: it names no mod/class, only scans loaded mods for a static `*bypass*(boolean)` switch and checks that method's bytecode via `ClassSafety.isMethodSafe`. Do not hardcode a mod's class there.
- `/wyp kill` must always bypass protections: gate new protection on `KillUtil.isForceKilling(entity)`.
- The `/wyp` tree is deliberately small (trimmed in 1.4.0): the self-limits (walk/fly speed, mining speed and interval, jump, step, attribute lists, reset) are edited only in the Cloth panel (`/wyp panel`, client-side, saved through `PacketUpdateLimits`) and have no commands; the "honor" kill is the trailing literal `/wyp kill [targets] honor` instead of a separate `/wyp killhonor`; grants are `/wyp access grant|revoke noupdate [players]`. `/wyp status [player]` stays because it can also report another player's limits (the panel is self-only). Do not re-add limit-setting subcommands.
- `api/WieldYourPowerApi` is the public surface for KubeJS/other mods: force break, no-update break, no-update place (facade over `util/ForceBlockBreak` and `util/NoUpdateMode`), plus `setSurvivalNoUpdateAccess(player, allowed)` which grants a survival player the "no update" mode (player-facing name: "update suppression" / 「抑制更新」; server-side; the server also syncs the flag to that player's client so its prediction matches). Keep its signatures stable.
- Author's favor (`AuthorsFavorEvents`) coefficients default to "no effect" (`damageCoefficient` 1, `maxHealthCoefficient` 0, `maxHealthChangeCoefficient` 1) on purpose: opt-in per entity for pack authors. Don't "fix" the defaults. Entities are chosen by `authorsFavor.filter` (comma matchers `tag,`/`type,`/`uuid,`, parsed by `EntityMatcher`/`FilterSyntax`). It only touches `setHealth`/`die` calls that bypass the vanilla damage chain; vanilla damage is never modified. `damageCoefficient` is the fraction of the change that actually takes effect (`new = floor(before - (before - requested) * coefficient)`), so protection engages when it is below 1. With `damageCoefficient < 1` the per-tick fallback restore also revives a favored entity whose health was forced to 0 outside the vanilla chain, which fights scripted deaths; such bosses must not be favored. The restore paths (the per-tick fallback and the direct-`die()` branch) only act when the vanilla `DATA_HEALTH_ID` is also at or below zero, so an entity whose `getHealth()` is overridden by another mod (its vanilla field stays positive) is left to that mod's own death handling instead of being resurrected. A favored entity that is still alive drops no death loot (`LivingEntityDropLootMixin`), so forcing `dropAllDeathLoot` cannot hand out kill rewards for a survived purge.
- Keep `assets/wieldyourpower/lang/en_us.json` and `zh_cn.json` in sync.
- `Reference/` is extracted third-party material (gitignored, study only); nothing there is compiled or shipped.
- Do NOT publish GitHub Releases or version tags for this project. Source only, so anyone who wants the mod must build it themselves - a small barrier against misuse. Releases/tags are removed on purpose.
